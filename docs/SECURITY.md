# WATHB — نموذج التهديد والأمن

> **المعيار الأمني الموحد (إصدار 1.0، 2026-10-28):** يطبق على كامل نطاق المنتج. هذه ضوابط تصميم لم تنفذ أو تختبر بعد.

## الأصول والتهديدات

الهوية والجلسات، الملفات والاتصالات والخصوصية والموقع، الصداقات والمحتوى، سعة الأنشطة والحضور والنتائج والفرق والتقييمات، البلاغات ومفاتيح الخدمات. التهديدات: استيلاء حساب/تعداد، تجاوز RLS، دعوة أو تعليق مسيء، تزوير حضور/نتيجة، سباق سعة، تكرار عملية، تلاعب تقييم، رفع ملف ضار، كشف موقع أو secret، وإساءة استخدام صلاحية المشرف.

## ضوابط إلزامية

1. **هوية:** رسائل لا تكشف وجود الحساب؛ تأكيد البريد واستعادة مضبوطة؛ تخزين refresh token آمن بالمنصة وإبطال عند الخروج/الحذف؛ limits خادمية؛ الروابط العميقة تتحقق من الرمز والهدف. Google/Apple فقط بعد إعداد redirect ومراجعة كل منصة.
2. **تفويض:** RLS وgrants على كل جدول/view مكشوف، default deny، فصل العرض العام عن الخاص. مراجعة كل `SECURITY DEFINER` و`search_path`. التحقق من `auth.uid()` داخل RPC. anon/publishable key فقط بالعميل؛ service_role وأسرار push على خادم محمي.
3. **سلامة العمليات:** معاملات وقفل وقيد فريد للسعة/العضوية/المراجعة، idempotency للدعوة والإشعار، تدقيق لتأكيد الحضور والنتيجة والتصحيح والفرق. القبول لا يتحول تلقائيًا لحضور؛ لا نتيجة/إحصاء/تقييم دون أهلية مثبتة.
4. **المحتوى:** أطوال محددة وتعقيم عرض التعليقات، إبلاغ/حظر وإشراف، قرار معلل ومراجع بشري عند الحاجة. رفع صور بقيد النوع الحقيقي/الحجم والأبعاد، حذف metadata، وتحديد من يستطيع القراءة. حماية من spam ومعدلات خادمية.
5. **خصوصية:** أقل جمع؛ إخفاء البريد والهاتف والموقع الدقيق افتراضيًا؛ إعداد لكل حقل؛ الاحتفاظ والحذف/التصدير موثقان؛ لا موقع مستمر دون ضرورة وموافقة؛ سجلات منقحة من PII والتوكن.
6. **تشغيل:** فصل البيئات والأسرار، فحص secrets واعتماديات، تدوير سر عند تسرب، نسخ احتياطي واستعادة مجربة، سجل تدقيق محدود، صلاحيات مشرف منفصلة. لا إنشاء cloud أو نشر قبل موافقة وقرار صريح.

## اختبارات أمن وقبول مرتبطة بالمراحل

- **P2:** مجهول لا يقرأ خاصًا؛ المستخدم A لا يعدل ملف/نشاط B؛ RPC ترفض معرفًا مزورًا؛ اختبار reset/session دون كشف حساب؛ فحص لا service_role في الحزمة.
- **P3:** المستخدم يرى ملفه وحقوله العامة فقط؛ طرف الصداقة الصحيح وحده ينتقل بالحالة؛ حظر يمنع تفاعلًا وفق السياسة؛ RLS للمجهول/طرف ثالث.
- **P4:** طلبا المقعد الأخير يعطيان قبولًا واحدًا؛ تكرار الاستجابة/تحديث webhook لا يكرر مقعدًا أو إشعارًا؛ تعليق لا يقرأه غير مخول؛ رابط الدعوة لا يوسع صلاحية المستخدم.
- **P5:** حضور لا يكتبه لاعب لنفسه؛ النتيجة لها فاعل/تاريخ واعتراض؛ تشكيل لا يكرر/يفقد عضوًا؛ غير حاضر لا يقيم لاعبًا/ملعبًا؛ تقييم ثانٍ مرفوض؛ حذف حساب يطبق الاحتفاظ المعلن.
- **P6:** اختبارات مصفوفة RLS شاملة، فحص أسرار/حزم، تحميل غير آمن، مراجعة خصوصية وسجل إدارة، اختبارات سباق. النتائج تسجل كما شغلت فعليًا.

## حوادث وقرارات خارجية

يلزم مالك للاستجابة للحوادث وإجراء تدوير المفاتيح والاستعادة. المناطق/مزودات Supabase وpush وخرائط وتخزين صور وحسابات المتاجر تتطلب قرار إعداد؛ لا بيانات اعتماد هنا. يلزم مراجعة قانونية/خصوصية لبلد الإطلاق والعمر والاحتفاظ والتعليقات والتقييمات قبل النشر. لا يُعرض badge أمني دون تدقيق فعلي.
